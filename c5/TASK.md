# C5: Windows Security log -> login sessions (browser + Node, no deps)
Work only in /Users/bryan/labmeter-demo/c5/. No git. ES5 style (var/function), UMD wrapper like ../rates.js:
`(function(root){ ... root.LBWinLog = API; if (typeof module!=="undefined") module.exports = API; })(typeof window!=="undefined"?window:globalThis);`

Files: winlog.js, winlog.test.js (node winlog.test.js prints "ok"), sample_security_log.csv (synthetic).

Input: text of a CSV exported from Windows Event Viewer (Security log) on instrument PCs. Typical header: `Keywords,Date and Time,Source,Event ID,Task Category` and often a 6th unnamed/“Description” column with the multi-line event message (quoted, contains lines like "Logon Type:\t\t2", "Account Name:\t\tjsmith", "Logon ID:\t\t0x3E7A1", "Workstation Name:\tFORTESSA-PC"). Some exports instead have explicit columns (e.g. "TimeCreated","Id","MachineName","TargetUserName","TargetLogonId","LogonType" from PowerShell Get-WinEvent | Export-Csv). Support BOTH: detect columns case-insensitively; if fields are not columns, extract them from the message text with regexes. For 4624 the NEW logon's account is in the "New Logon:" section (second "Account Name"/"Logon ID" occurrence after "New Logon:"); for 4634/4647 it's under "Subject:"/"Account Name".
Must include a proper RFC4180 CSV parser (quoted fields with commas/newlines/"" escapes; comma/tab/semicolon delimiter detection).

API:
- `isWinLog(headerArray)` -> true if headers contain an event id column ("Event ID" or "Id") and a time column ("Date and Time" or "TimeCreated").
- `toSessions(text, opts)` opts: {computer: default workstation name if none in data (e.g. from file name), maxHours: 12}. Returns {sessions:[{workstation,user,start,end,endReason}], warnings:[string], csv: string}.
  Rules: logon = Event 4624 with Logon Type 2 (interactive), 10 (remote interactive) or 11 (cached) — ignore type 3/5 and machine/system accounts (names ending with "$", SYSTEM, LOCAL SERVICE, NETWORK SERVICE, DWM-*, UMFD-*). Logoff = 4634 or 4647, matched by Logon ID (case-insensitive hex). If no logoff: end at the next qualifying logon on the same workstation (endReason "next-logon"), else cap at start+maxHours (endReason "capped"); add a warning listing count of unmatched logons. Also treat 4800 (lock) / 4801 (unlock): ignore for now (comment). Times: parse "M/D/YYYY h:mm:ss AM/PM" and ISO; output "YYYY-MM-DD HH:MM:SS" naive local (no timezone conversion). Sort by start.
  csv header exactly: `Workstation,Username,Logon Time,Logoff Time` (this is what the app's usage-log parser reads).
- sample_security_log.csv: synthetic Event Viewer export (with the 6th message column) for 2 workstations (FORTESSA-PC, SP8-WS01), users arjunpat, lmoreau, htanaka over 2 days in Oct 2026: include type 2 logons, matching 4634, one 4647, one missing logoff (should end at next logon), one type 3 network logon (ignored), one SYSTEM/DWM-1 logon (ignored), one machine account "FORTESSA-PC$". Mark as synthetic in a first-row? NO — CSV must start with the header; mention synthetic in winlog.js comment.
